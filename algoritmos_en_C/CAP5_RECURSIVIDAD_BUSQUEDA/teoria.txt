5.1 NATURALEZA DE LA RECURSIVIDAD 

la recursividad se puede redicir a una funcion que se llama a si misma bien directamente o bien a traves de otra funcion. la recursividad es un tipico importante examinando frecuentemente en curso y seminarios de resolucion de algoritmos y de estrucutrua de datos.

ejemplo 5.1 PG 139

un ejemplo muy comun es el factorial, en donde el faorual es la multiplicacion sucesiva de enfreste a atras 

n! = n * (n-1) * (n-2),...,1 

de modo que una defincion recursiva del metodo factorial n es: 

n! = n * (n-1)!

se puede solucionar este mismo progrma de igual froma como un algoritmo iterativo. el cual podria seminarios

factorial =1; 

for(contador = n;  contador >= 1; contador --){
    factorial *= contador; 
}

pero utilizando un algoritmo recursvo debemos tener varias aspectos en cuenta 

- debemos de tener en cuenta la opcion en donde la funcion no se llama a si misma, en decir debemos te tener la condicion en donde el algoritmo se puede solucionar sin la recurcbidad porque debe de haber una parada. 

en el caso del factorial seria cunado el numero es 1, porque 1 x 0 = 0, entonces la funcion se llamara  si misma hta que <<n = 1>>

el algoritmo que resulve n! de modo recursivo se apoya en la defincion sigueinte: 

n! = 1            si n = 0

n! = n * (n -1)!  si n > 0

por lo que el algrimtos que calcula el factorial sera: 

long factorial(int n)
{
    if(n == 0){
        return 1;
    }
    else{
        return n*factorial(n-1);
    }
}

5.3 REURSION VS ITERACION  PG 145 

cuanto tomar a decision de solunar por iteracion y cunado por recursion? 

tanto la iteracion como la recursion se basan en una estructrua de controla: << la iteracion utiliza una estrucuura repetitiva>> y la recursion <<utliza una estrucutura de seleccion>>, la iteracion y la recursion implican ambas un test de terminacion. a iteracion termina cunado la condicion de bucle no se cumple mientras que la recursion termina cunado se conoce un caso base. 

un engoque recrusivo se elige nromalmente con preferencia a un enfoque iterativo cunado el enfoque ecursivo es mas natral para la resolucion del problema y produce un programa mas facil de comprender y depurar. 

consejo: 
<<
se ha de evitar recursividad en situaciones de rendimineto critico o exigencia de altas prestaciones en tiempo y memoria, ya que las llamadas recursias emplean tiempo y consumen memoria adicional.
>>

la busqueda binaria es una metodo de localizacion de una clave especifica dentro de una lista o arreglo << ORDENADO, la buqueda binaria funciona si el arreglo esta ordenado >> de n elemntos que realiza una exploracion de la lista hasta que se enceuntra o se decide que no se enceuntra en la lista. 

el algoritmode busqueda binaria se puede describir recrsivamente aplicando la tecnica de divide y venceras. 

se tiene aun lista odenada << a[] >> con un limite inferior y un limite superior. dada una clave (valor buscado), se comienza la busqueda en a posicion central de la lista. 

<<
centra = (inferior + superior)/2   ->  comparar a[central1] y clave
>>

si se produce coincidencia se tiene la condicion de la terminacion que permite detener la buqueda y devolver el indice central. se centra la busquda en la sublista <<subisa inferior - a la izquierda de la osicion centrla>> o en la << sublista derecha - a la derecha de la pisicion central>> 

- la busqueda lo que hace es dividir el arreglo a la mitad y comprara el elemento del indice que esta a la mitad de ese, es mayor al buscar buscaremos en su indice derecho, y aplicamos lo mismo, pero si es menor buscamos en el idnice izquierdo. en el caso que vaya de menor a mayor.

5.7 backtracking, algoritmo de vuelta atras PG 158

la resolucion de algunos probelmas exige probar sistematicamente todas las posibilidades que pueden existir para encontrar la solucion. 

los << algoritmos de vuelta atras >> utilizan la recurividad para probar cada unas de las pisibilidades de encontrar la solucion. 

estos algoritmos descomponen el proceso de busqueda o tanteo de una solucion en tareas parciales. cada tarea parcial realiza las mismas acciones que la tarea anterior y por eso se expresa frecuencetemente en forma recursiva. 

el proceso general de los algoritmos de << backtracking >> se completa como un metodo de prueba o busuqeda que gradualemnte construye tareas basicas y las inspecciona para determinar si conducen a la solucion del problema. 
es una prubea sistematica hasta llegar a la solucion o bien determinaar que no hay solucion por haberse agostado todas las opciones que probar. 

esque genral de estos algoritmos 

SUBPROGRAMA ensayarSolucion

INICIO
    < inicalizar cuenta de posibles selecciones >
    REPETIR 
        < tomar sigueinte seleccion (tarea) >
        < determinar si seleccion es valida >
        SI valido ENTONCES 
            <anotar seleccion >
            SI < problema solucioad > ENTONCES
                exito = true
            SI NO 
                ensayarSolucion (llamara para relaizar otra tarea)(vuelta atras, se analiza si se ha alcanzado la solucion del problema)
            SI NO exito ENTONCES
                <borrar anotacion> (el buvle se encarga con ptra seleccion)
            FIN_SI
        FIN_SI
    FIN_SI
hasta(exito) o ( <no mas posibilidades> )
fin
